## 入力範囲の注意

この版のディレクトリ要約では、各ファイルの先頭500文字、抽出した関数などの宣言（最大20件）、依存（最大15件）、複雑度の情報をLLMへ渡しています。構造化データの抽出は渡された材料だけで行い、後続の構成調査や文書作成の一部で読み取り用ツールを使えます。探索した84ファイルをすべて全文精査したという意味ではありません。

実装の根拠はLithoの [`directory_summary.rs`](https://github.com/sopaco/deepwiki-rs/blob/c62a54d4980c6c00e8551aaf128f0229f93f5b92/src/generator/preprocess/agents/directory_summary.rs) です。たとえば `score.rs` の中間要約は、共通の計算処理と評価方式の識別子を説明しています。ただし計算式が正しいかは、要約の読みやすさではなく、対象コードの `src/balance/score.rs` と照合して確かめる必要があります。

## 構成調査の指摘をコードと照合

Lithoの構成調査から、Web画面の外部CDN依存とコンテナの待受アドレスについて確認点が得られました。いずれも次のコード・設定と照合しています。コンテナ実行やネットワーク遮断の試験は実施していません。

指摘された箇所を変更する場合は、必要な利用条件を決めてから、該当する動作を検証します。ドキュメント生成の依頼内では、対象ツールの動作を変更していません。

境界の調査結果は `/api/design` のHTTPメソッドを未確認と記録しました。この段階の入力は要約が中心です。`src/web/design.rs` の `routes` を読むと、`get(get_design)` によってGETで公開されていることを確認できます。`/api/impact` も同じ箇所でGETとして定義されています。元の調査応答は `.litho/cache/studies_research/Boundary Interface Research Report/` に残しています。
