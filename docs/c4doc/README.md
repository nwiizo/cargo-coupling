# Inside cargo-coupling

A terminal report and an interactive graph start with the same Rust analysis. Follow a project from Cargo and Git into design assessment, then trace a browser request that compares a revision. These four views are for Rust developers who want to use the tool or change how it works.

## Explore the architecture

Follow the views in order, or jump to the question you have.

1. [What can I learn about my code?](context.md) · System context

   cargo-coupling helps you inspect structural coupling and change history when deciding where to refactor. Use the CLI for reports or open the Web UI to explore the results.

2. [Where does the analysis run?](containers.md) · Container

   Rust analyzes the project in the native application; the browser displays its results over HTTP. Switching to --web starts the embedded server in that same application.

3. [What do the CLI and Web UI share?](components.md) · Component

   Both entry points call the same design assessment. That shared responsibility coordinates coupling evaluation and revision comparison, so developers can begin there when changing assessment behavior.

4. [What happens when I compare against HEAD?](compare_request.md) · Dynamic

   For a successful Web comparison, the server first checks that the source still matches its startup snapshot. It then passes startup metrics and HEAD to the shared assessment and returns JSON for the browser to display.
