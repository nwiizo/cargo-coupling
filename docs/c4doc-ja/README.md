# cargo-coupling のしくみをたどる

ターミナルのレポートも、操作できるグラフも、出発点は同じ Rust の解析処理です。Cargo と Git から設計評価へ、さらにブラウザからリビジョンを比較する一連のやり取りへと進みます。ツールを使う人にも、実装を変更する人にも役立つよう、4 つの図でしくみをたどります。

## Explore the architecture

Follow the views in order, or jump to the question you have.

1. [自分のコードについて、何が分かる？](context.md) · System context

   cargo-coupling は、構造上の結合と変更履歴を調べ、リファクタリングする場所を考えるためのツールです。CLI でレポートを読むことも、Web UI で結果を探索することもできます。

2. [解析はどこで動く？](containers.md) · Container

   ネイティブアプリケーション内の Rust がプロジェクトを解析し、ブラウザは HTTP で受け取った結果を表示します。--web に切り替えると、そのアプリケーション内で組み込みサーバーが起動します。

3. [CLI と Web UI は、何を共有している？](components.md) · Component

   どちらの入口も、同じ設計評価処理を呼び出します。この処理が結合度の評価とリビジョンの比較をまとめているため、評価の動作を変更するときの出発点になります。

4. [HEAD との比較を頼むと、何が起きる？](compare_request.md) · Dynamic

   Web の比較が成功する経路では、まずサーバーが起動時からソースが変わっていないことを確かめます。その後、起動時のメトリクスと HEAD を共通の設計評価処理へ渡し、ブラウザに表示する結果を JSON で返します。
