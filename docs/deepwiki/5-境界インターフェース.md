# 境界インターフェース

Lithoが生成した境界の説明へ、コードとCLIヘルプで確認できた入力・公開パスを補った文書です。生成時には `/api/design` のHTTPメソッドなどが未確認でした。元の応答と、補足した理由は[実行記録](../litho-run.md)に残しています。HTTPの説明はコード照合に基づき、Webサーバーを起動した通信試験は行っていません。

## CLI

入口は `cargo coupling` です。対象パスと表示・比較条件を受け取り、共通のRust解析を呼び出します。対象版の全オプションは次で確認できます。

```sh
rtk proxy cargo coupling --help
```

| 目的 | 入力例 |
| --- | --- |
| 結合の解析 | `cargo coupling .` |
| 設計評価をJSONで取得 | `cargo coupling --design --json .` |
| 追加の設計情報を使う | `cargo coupling --context docs/examples/design-context.toml .` |
| 変更基準から影響を追う | `cargo coupling --changed-since main --impact-depth 4 .` |
| 基準に対する新規・悪化した問題を検査 | `cargo coupling --check --baseline main .` |
| Web画面を起動 | `cargo coupling --web --no-open .` |

設定例の担当者、予定、見積もりは例示用です。そのまま実際の判断材料として扱わず、自分たちの情報へ置き換えます。品質ゲートの判定と出力モードの関係は[分析結果の活用・品質ゲート](4-詳細探索/分析結果の活用・品質ゲート.md)を参照してください。

入力の根拠は [main.rs](../../src/main.rs) の `Cli`、`Commands`、`Args` です。生成後の確認では、このチェックアウトからビルドしたCLIの `coupling --help` と `coupling --design --exclude-tests --json .` を実行しました。

## HTTP API

[web/routes.rs](../../src/web/routes.rs) と [web/design.rs](../../src/web/design.rs) のルーターで、次のGETエンドポイントを確認できます。クエリ名も同じファイルの入力構造体から確認しました。

| メソッド・パス | クエリ | 主な用途 |
| --- | --- | --- |
| `GET /api/graph` | `ref`（任意） | 現在または指定リビジョンのグラフ |
| `GET /api/report` | なし | 解析レポート |
| `GET /api/history` | なし | 履歴情報 |
| `GET /api/config` | なし | フロントエンド向け設定 |
| `GET /api/health` | なし | 固定文字列 `ok` |
| `GET /api/source` | `path`（必須）、`line`・`context`・`ref`（任意） | 現在または過去のソースの抜粋 |
| `GET /api/module` | `name`（必須） | 指定モジュールの要素 |
| `GET /api/design` | `changed_since`・`depth`（任意） | 起動時の設計評価、またはGit基準との比較 |
| `GET /api/impact` | `module`（必須）、`depth`（任意） | モジュールを起点に影響を追跡 |

`/api/design` は `DesignQuery` を受け取り、`changed_since` が空または未指定なら起動時の設計評価を返します。比較を指定したときは、ソースが起動時から変わっていないかを確認し、共通の `assess` で比較します。変わっていればHTTP 409を返します。`depth = 0` はHTTP 400です。

`/api/impact` は `ImpactQuery` を受け取り、起動時の解析結果から影響を追います。`module` が見つからない、または名前が曖昧な場合はHTTP 404を返します。指定するモジュール名は、対象プロジェクトの解析結果から確認してください。

ソース取得では対象パスを検査します。パス検査と利用者の認証は別の役割です。この一覧は、共有ホスティングやインターネット公開の安全性を確認したものではありません。待受アドレスや外部CDNについては[アーキテクチャ概要](2-アーキテクチャ概要.md)を参照してください。

## Web画面とURL

`GET /` は `index.html` を返し、`GET /{*path}` は組み込みアセットを配信します。実装は `web/routes.rs` の `static_routes`、`index_html`、`static_handler` です。

[url-router.js](../../web-assets/js/url-router.js) の `getInitialSelection` は、URLのクエリから次の値を取得します。

| キー | 初期値の扱い |
| --- | --- |
| `module` | 指定された文字列。空または未指定なら `null` |
| `item` | 指定された文字列。空または未指定なら `null` |
| `view` | 指定された文字列。空または未指定なら `null` |
| `items` | 文字列 `true` の場合だけ真 |

ここで確認したのはURLの読み取りです。存在しない識別子や画面状態の組み合わせの扱いは、画面側の処理と併せて確認します。共有URLの生成には `buildShareUrl` など、既存の生成処理を使います。

## 設定・外部環境との接点

| 入力 | 内容と確認先 |
| --- | --- |
| `.coupling.toml` | 閾値、除外、変動性、サブドメインなどの解析設定。`src/config.rs` |
| `.coupling-context.toml` または `--context` | 担当者、変更予定、業務ルール、実行時の前提、シナリオ、判断理由。`src/design/context.rs` |
| CODEOWNERS | 担当者の情報を補完。`src/design/organization.rs` |
| Cargo | ワークスペースと依存情報の取得 |
| Git | 変更頻度、同時変更、差分、過去リビジョンの参照 |
| ローカルファイルと一時領域 | ソース・設定・出力の読み書き、履歴解析の一時worktree |
| ブラウザと外部CDN | Web表示と可視化ライブラリなどの取得 |

設計情報の形式と検証条件は、既存の[設計分析資料](../design-analysis.md)を参照してください。観測した変更履歴と、利用者が記入した予定や見積もりは区別して扱います。
